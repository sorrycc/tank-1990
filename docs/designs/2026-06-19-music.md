# Tank 1990 — Music / jingle (synthesized, zero new assets)

## 1. Background

F6 added `src/audio/Sound.ts` — the single procedural WebAudio façade (zero asset files; every sound
synthesized from `_tone`/`_noise` through gain envelopes) — and a later step extended it with the
lifecycle SFX (`stageStart`, `respawn`, `uiMove`, `denied`, `itemDrop`). All of it is **one-shot
fire-and-forget transients**: a `_gateOk` throttle, then a handful of short oscillators that auto-stop.
There is **no sustained music** anywhere — the Title screen and the stage curtain are silent of melody.
The user asked for synthesized background music: a short looping **Title theme**, a **stage-start jingle**,
and optionally a brief **game-over sting** — all WebAudio, no asset files, respecting the M mute, and a
safe no-op under the NoAudio path.

## 2. Requirements Summary

- **Goal:** Add synthesized music to the existing single audio owner (`Sound.ts`): (1) a short looping
  Title theme, (2) a stage-start jingle on the GameScene curtain, (3) a brief game-over sting.
- **Scope:** Extend `Sound.ts` with a tiny note-sequencer + a self-rescheduling melody/loop player built
  ONLY from the existing `_tone` primitive; wire the Title theme to `TitleScene` (start on `create`, stop
  on scene `shutdown`); wire the jingle to the GameScene curtain; play the game-over sting from GameScene.
- **Non-goals (explicit):** no asset files / no `load.*`; no multi-track mixer, no tempo ramp, no chiptune
  engine (YAGNI — a square-wave melody over the master gain is enough); no new `src/config/*` or
  `constants.ts` numbers (music tempo/notes are audio-only tunables that belong beside `MASTER_GAIN` in
  `Sound.ts`, the existing convention — see Decision 4); the headless verifier stays green (it never
  imports `Sound.ts` or scenes).

## 3. Key Decisions

**D1. Where does the music live — entity/scene or the façade?**
The façade. `Sound.ts` is the SINGLE audio owner (the F6/D6 stance). Music is just a *sustained* sound, so
it gets new semantic methods on `Sound` (`titleMusicStart()` / `musicStop()` / `stageJingle()` /
`gameOverSting()`), called from the scene orchestrators — exactly like every existing `sfx.*` call.

**D2. How does a LOOP work given every primitive is fire-and-forget?**
A self-rescheduling melody player. The looping Title theme is NOT one long buffer; it is a small note
array `[{freq, beats}, …]` played one `_tone` per note on the WebAudio clock, with a `setTimeout`
(`scene.time` is not used — music must survive the run-end gameplay freeze, exactly like the SFX schedule
on `ctx.currentTime`, §5.2 of `Sound.ts`) re-arming the same player at the end of the bar. KISS: one
private `_loopTimer: ReturnType<typeof setTimeout> | null` field guards/stops it. The **jingle** and
**sting** are one-shot melodies that reuse the SAME sequencer but do NOT re-arm — so a melody player +
a "loop?" flag is the only new machinery (DRY: the loop, jingle and sting share one `_playSequence`).

**D3. Mute + NoAudio + persistence.**
The existing `_gateOk` / context guards already make every per-note `_tone` a no-op under NoAudio and when
`this.sm.mute` is set. For the LOOP we additionally guard `titleMusicStart()` (don't even arm the timer if
there's no ctx) and make each re-arm re-check `this.ctx`/`mute` before scheduling the next bar — so toggling
M mid-theme silences the notes immediately (each note bails via `_gateOk`) and the loop self-stops cheaply.
"Persisted mute" — the M toggle is Phaser's GLOBAL mute (runtime only; the brief's "persisted" maps to
Phaser's mute being honored by the same `this.sm.mute` check every note already does). No save-schema field
is added (YAGNI — matches the existing D8 mute stance).

**D4. No new shared constants.**
Music tempo (BPM), the master music gain, and the note tables are **audio-only tunables** — they have no
meaning outside the synth. They live as module-local consts beside `MASTER_GAIN`/`THROTTLE_GAP` in
`Sound.ts` (the established home for audio tunables), NOT in `config/constants.ts`. This keeps the
pure/coupled split clean (constants.ts stays Phaser-free DATA shared across modules; these are not shared).

**D5. Keep it tasteful + non-blocking.**
The melody is quiet (a dedicated `MUSIC_GAIN` well under the SFX peak so shots/explosions sit on top), the
Title loop is a short ~8-note phrase, the jingle ~4 notes, the sting ~3 notes. Music NEVER blocks gameplay:
it is fire-and-forget on the audio clock; nothing awaits it. The stage jingle is a brief flourish layered
over the curtain — it does not gate the curtain timer.

**D6. Title theme start/stop lifecycle.**
`TitleScene.create()` calls `sfx.titleMusicStart()`. The theme must STOP when the player leaves Title (so it
doesn't bleed into the Hub). TitleScene has no `shutdown` hook today → add
`this.events.once(Phaser.Scenes.Events.SHUTDOWN, () => sfx.musicStop())`. The first user gesture also resumes
the suspended context, so the very first loop iteration may be silent until the context starts — acceptable
(the same caveat the Title's `uiSelect` already documents), and the re-arm picks it up on the next bar.

**D7. Stage jingle vs. the existing `stageStart()` SFX.**
`GameScene._buildStage()` already plays the `stageStart()` two-note "get-ready" SFX as the curtain arms.
The MUSIC jingle is a SEPARATE, slightly longer melodic flourish (its own method + own throttle key) played
at the SAME site. To avoid a muddy stack we play the jingle and DROP the redundant tiny `stageStart()` is
NOT done (KISS — they have distinct keys and the jingle is the richer cue); instead the jingle is the
primary stage cue and `stageStart()` stays as the short transient under it. Reversible: if it sounds busy in
review, the one-line `stageStart()` call can be removed (Phase 4).

## 4. Design — exact changes

### `src/audio/Sound.ts` (the only synthesis change; additive)

- New module-local tunables beside `MASTER_GAIN`/`THROTTLE_GAP`:
  `MUSIC_GAIN = 0.12` (quiet — SFX sit on top, D5), `MUSIC_BPM = 132` (→ `_beat = 60/BPM` seconds/beat).
- New types: `Note = { freq: number; beats: number }` (a tiny step; `freq <= 0` = a rest), `Melody = Note[]`.
- Three module-local melody tables (square-wave, programmer-art chiptune): `TITLE_THEME` (~8 notes, a
  loopable phrase), `STAGE_JINGLE` (~4-note rising flourish), `GAME_OVER_STING` (~3 descending notes).
- New private field `_loopTimer: ReturnType<typeof setTimeout> | null = null` (the loop re-arm handle).
- New private `_playSequence(mel: Melody, gain: number): number` — schedules one `_tone({type:'square'})`
  per non-rest note on `ctx.currentTime` with a running `delay` accumulator (`beats * _beat`), returns the
  melody's total duration (s). Per-note volume = `gain` (×MASTER_GAIN×volume happens inside `_tone`). No
  `_gateOk` per note (the player owns scheduling); a single context/mute check up front.
- New public methods (each context/mute-guarded, NO-OP headless):
  - `titleMusicStart()` — guard (ctx + not muted); `musicStop()` first (idempotent); play `TITLE_THEME`,
    then `_loopTimer = setTimeout(() => this.titleMusicStart(), durationMs)` to re-arm the next bar. A
    mute/teardown between bars stops the re-arm (the guard bails → no further `setTimeout`).
  - `musicStop()` — `if (this._loopTimer) clearTimeout(this._loopTimer); this._loopTimer = null`. Already
    scheduled notes tail out naturally (they're short); a hard kill isn't needed (KISS). Safe to call when
    nothing is playing (the Title shutdown + any future caller).
  - `stageJingle()` — `_gateOk('stageJingle', 0.3)` then `_playSequence(STAGE_JINGLE, …)` (one-shot, no loop).
  - `gameOverSting()` — `_gateOk('gameOverSting', 0.5)` then `_playSequence(GAME_OVER_STING, …)` (one-shot).

  Heavy explanatory comments in the existing house style (why a `setTimeout` re-arm not a gameplay timer;
  why no per-note `_gateOk`; the mute/NoAudio no-op story).

### `src/scenes/TitleScene.ts`

- In `create()`, after `const sfx = new Sound(this)`: `sfx.titleMusicStart()`.
- Register the stop on leave: `this.events.once(Phaser.Scenes.Events.SHUTDOWN, () => sfx.musicStop())`
  (Phaser is already imported here). This is the ONLY structural add (one start + one shutdown listener).

### `src/scenes/GameScene.ts`

- In `_buildStage()`, beside the existing `this.sfx.stageStart()` (~L443): add `this.sfx.stageJingle()`.
- In `_triggerGameOver()`, beside the existing `this.sfx.gameOver()` knell (~L950): add
  `this.sfx.gameOverSting()` (the melodic sting layered over the knell — D5/§4).

No other scene touches music. The Hub/GameOver scenes stay music-free (the loop is Title-only by design — D6).

## 5. i18n

**None.** Music has no user-facing strings (the audio façade has none — same as the SFX step). No keys added
to `en.ts` / `zh-CN.ts`.

## 6. Acceptance Criteria

1. `Sound.ts` gains `titleMusicStart()`, `musicStop()`, `stageJingle()`, `gameOverSting()`, a private
   `_playSequence()`, a `_loopTimer` field, and the `MUSIC_GAIN`/`MUSIC_BPM` + three melody tables — all
   built ONLY from the existing `_tone` primitive; NO new asset files, NO `load.*`, NO Phaser import added.
2. The Title screen plays a short looping square-wave theme on entry; it STOPS (no bleed into the Hub) when
   the start gesture leaves Title (SHUTDOWN listener).
3. Each stage's intro curtain plays the stage jingle (first stage + every advance); the run-end plays the
   game-over sting alongside the existing knell.
4. Toggling M silences the music immediately (every note bails via the shared ctx/mute guard) and the loop
   self-stops between bars; under the NoAudio path every music method is a safe no-op that never throws.
5. Music never blocks gameplay (fire-and-forget on the WebAudio clock; no awaited timer, no curtain gating).
6. `npm run typecheck`, `npm run build`, and `npm run verify` ALL pass.

## 7. Keeping `npm run verify` green (pure/coupled split + determinism)

- All changes are confined to `src/audio/Sound.ts` (Phaser-coupled — WebAudio) and two scenes — the
  verifier NEVER node-imports any of these (it imports only the pure `config/*` + `world/LevelGenerator.ts`
  + `util/*` + `i18n/*` modules; §1 of `scripts/verify-gen.mjs`). No pure module gains a Phaser import.
- No `config/constants.ts` change (music tunables are audio-local — D4), so the constants invariants the
  verifier checks are untouched.
- Music is non-deterministic-free of the SEEDED simulation: it schedules on the audio clock and never feeds
  the RNG / generator / RunState, so the determinism + monotonicity gates (the seeded-stage sweep) are
  entirely unaffected.

## 8. Files Changed

- `src/audio/Sound.ts` — add `MUSIC_GAIN`/`MUSIC_BPM`, `Note`/`Melody` types, three melody tables, the
  `_loopTimer` field, `_playSequence()`, and `titleMusicStart`/`musicStop`/`stageJingle`/`gameOverSting`.
- `src/scenes/TitleScene.ts` — start the theme in `create()`; stop it on the SHUTDOWN event.
- `src/scenes/GameScene.ts` — `stageJingle()` in `_buildStage()`; `gameOverSting()` in `_triggerGameOver()`.
