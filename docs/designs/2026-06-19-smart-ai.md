# Smarter AI — eagle-rush cohort + aimed firing + type flavor in Tank.updateAI

## 1. Problem / Intent

The F4 enemy AI (`entities/Tank.updateAI`) is a thin wander/seek FSM: every re-decide it steps the
Manhattan-greedy cardinal toward the nearest of {eagle, players} with probability `AI_SEEK_BIAS`, else
a random wander, and it FIRES on every cooldown beat regardless of where it is pointing. Two felt gaps:
(a) NO real base pressure — every enemy treats the eagle and the players symmetrically, so the eagle is
rarely rushed; (b) shots look RANDOM — a tank fires the instant its cooldown clears even when aimed at a
wall, so bullets feel sprayed, not intentional. The four archetypes also play identically in motion
(only their stat magnitudes differ).

GOAL — deepen the SAME intent-producer FSM (no A*, no new movement path):
1. **Eagle-rush cohort** — a configurable fraction of enemies HARD-COMMIT to the eagle (a high per-tank
   seek bias toward the eagle, ignoring the closer-player retarget) so there is real base pressure.
2. **Aimed firing** — an enemy only sets `firePressed` when it is roughly AXIS-ALIGNED with a target
   (eagle or a player) within a tolerance, so shots read as intentional.
3. **Light type flavor** — `fast` flanks/wanders more, `power` holds lanes + shoots aligned, `armor`
   pushes straighter toward the base. A per-type tweak of the EXISTING seek-bias / alignment knobs only.

## 2. Key Decisions

1. **Per-tank AI profile resolved ONCE in the ctor, not per frame (KISS/DRY).** `updateAI` already reads
   per-tank fields (moveSpeed, fireCooldown). Add three per-tank AI fields — `aiSeekBias` (the effective
   seek probability), `aiRushEagle` (bool — this tank is in the eagle-rush cohort → always targets the
   eagle), `aiAimTolerance` (px half-width of the "aligned enough to fire" band). They are derived once in
   the ctor from `spec.behavior` + the new constants (a small `switch`/lookup), so the per-frame tick stays
   branch-light and there is ONE place type flavor is decided. NO new spec fields in `tanks.ts` (the flavor
   is AI feel keyed off the existing `behavior` tag, not a tunable the verifier sweeps — YAGNI/SOLID).

2. **Eagle-rush is a spawn-time COIN FLIP, not a spec field (KISS).** A fresh enemy's `aiRushEagle` defaults
   false in the ctor; the SCENE flips it on spawn with `enemy.aiRushEagle = this.stageRng() < AI_EAGLE_RUSH_RATE`
   — exactly the `enemy.carrier = this.stageRng() < CARRIER_RATE` pattern two lines away (DRY). Using
   `stageRng` (the seeded stream) keeps the COHORT MEMBERSHIP a stage-seed fact; the in-tick wander/seek/aim
   rolls stay on runtime `Math.random()` (Decision 6). Boss + player never set it (left false).

3. **Target selection respects the rush flag (the base-pressure mechanic).** In the re-decide block, when
   `aiRushEagle` is true the tank targets the eagle UNCONDITIONALLY (skip the closer-player loop); otherwise
   the existing "eagle, or nearer live player" pick is byte-unchanged. A rush tank's seek bias is also raised
   (its `aiSeekBias` is set high in Decision 1), so it both COMMITS to the eagle and wanders less — real
   pressure without pathfinding (the carved corridor to the fort already guarantees reachability — D4 of F4).

4. **Aimed firing = an alignment gate ANDed onto the existing fire decision (SOLID, additive).** Today the
   non-telegraph branch sets `firePressed = cooldownTimer <= 0`. Add an `_aimedAtTarget()` helper that
   returns true when SOME target (eagle, or any live player) lies within `aiAimTolerance` px on the cross
   axis of the tank's current facing AND on the correct side (in front of the barrel). The fire decision
   becomes `firePressed = cooldownTimer <= 0 && this._aimedAtTarget(ctx)`. This wraps BOTH the immediate
   path AND the boss telegraph ARM (a boss only winds up a shot when it has a line) — one helper, both
   paths (DRY). The aim test reuses `ctx.eagle`/`ctx.players` already passed in — NO new ctx field.

5. **Tunables live ONCE in `constants.ts` (DRY).** Add `AI_EAGLE_RUSH_RATE` (fraction of the cohort),
   `AI_SEEK_BIAS_RUSH` (the raised seek bias for a rusher), `AI_AIM_TOLERANCE` (px alignment band), and
   the small per-type seek-bias flavor lives as a derivation off the existing `AI_SEEK_BIAS` anchor inside
   the ctor switch (e.g. `fast` ×0.8 wanders more, `armor` ×1.15 pushes straighter) — NO per-type constant
   sprawl; the anchor stays the single owner and the multipliers are inline, intent-commented (KISS/YAGNI).

6. **Determinism stays OFF the pin (the F4 contract is preserved).** The in-tick wander/seek/aim rolls
   keep using runtime `Math.random()` exactly as today — the verifier never imports `Tank.ts`, so AI
   randomness is invisible to the determinism pin. The ONLY seeded draw added is the cohort coin flip in
   the scene's `_spawnStep`, which uses the EXISTING `stageRng` stream the spawn loop already advances
   (rosterPick + carrier flip), so the stage's RNG consumption pattern is a documented, contained change
   that does NOT touch `LevelGenerator`/`generateStage` (the verifier's stage gate is byte-unaffected).

## 3. Files to touch

- **`src/config/constants.ts`** (PURE) — add `AI_EAGLE_RUSH_RATE` (0..1 cohort fraction),
  `AI_SEEK_BIAS_RUSH` (0..1 raised seek bias), `AI_AIM_TOLERANCE` (px alignment band) beside the existing
  `AI_SEEK_BIAS`/`AI_REDECIDE_*` block, in the F-feature heavy-comment style. The single PURE owners (DRY).
  No Phaser import (purity preserved).

- **`src/entities/Tank.ts`** (Phaser-coupled) —
  - Import `AI_EAGLE_RUSH_RATE` is NOT needed here (the scene owns the flip); import `AI_SEEK_BIAS_RUSH`,
    `AI_AIM_TOLERANCE` (and the existing `AI_SEEK_BIAS`).
  - Add per-tank fields: `aiRushEagle: boolean` (default false), private `aiSeekBias: number`,
    `aiAimTolerance: number`. Derive `aiSeekBias`/`aiAimTolerance` ONCE in the ctor via a small
    `switch (spec.behavior)` off the `AI_SEEK_BIAS`/`AI_AIM_TOLERANCE` anchors (the type flavor — D5).
  - In `updateAI`'s re-decide block: when `aiRushEagle`, target the eagle unconditionally + use
    `AI_SEEK_BIAS_RUSH`; else keep the existing closer-player pick + use the per-tank `aiSeekBias`
    (replacing the bare `AI_SEEK_BIAS` read at the seek roll — D1/D3).
  - Add a private `_aimedAtTarget(ctx)` helper (D4): true iff a target is within `aiAimTolerance` on the
    facing's cross axis AND in front of the barrel. AND it onto BOTH fire branches' `firePressed`
    (immediate path) and the boss telegraph-ARM condition (D4).
  - Reset of these fields is unnecessary across respawn (enemies never respawn; the boss never respawns)
    — but `aiRushEagle` defaulting false in the ctor keeps players/boss byte-unchanged.

- **`src/scenes/GameScene.ts`** (Phaser-coupled) — in `_spawnStep`, after `enemy.carrier = …`, add
  `enemy.aiRushEagle = this.stageRng() < AI_EAGLE_RUSH_RATE` (the cohort flip — D2). `_spawnBoss` leaves
  it false (the boss already commits via its own AI). Import `AI_EAGLE_RUSH_RATE` from constants.

NO change to any PURE module beyond the additive constants. `tanks.ts`, `LevelGenerator.ts`, `tiles.ts`,
`stages.ts`, and the verifier-imported set are otherwise untouched.

## 4. Acceptance criteria

1. A configurable fraction (`AI_EAGLE_RUSH_RATE`) of spawned enemies HARD-COMMIT to the eagle: they target
   the eagle regardless of a closer player and seek it at the raised `AI_SEEK_BIAS_RUSH` — visible base pressure.
2. Non-rush enemies are unchanged in target selection (eagle, or a Manhattan-nearer live player).
3. An enemy fires ONLY when roughly axis-aligned with a target within `AI_AIM_TOLERANCE` AND the target is
   in front of its barrel — no more firing at walls/empty lanes on the bare cooldown beat.
4. The boss only ARMS its telegraph wind-up when it has a line on a target (the aim gate wraps the ARM too);
   its telegraph/fire timing is otherwise byte-unchanged.
5. Type flavor reads at runtime: `fast` wanders more (lower seek bias), `armor` pushes straighter (higher),
   `power` holds lanes + shoots aligned — all via the per-tank `aiSeekBias`/`aiAimTolerance` derived once.
6. The no-diagonal movement spine is byte-unchanged (this feature only changes the INTENT producer + the
   fire gate; `update()` and `_recenterCross` are untouched).
7. `npm run typecheck`, `npm run verify`, and `npm run build` all stay green.

## 5. How `npm run verify` stays green

- The verifier node-imports ONLY PURE modules (`config/*`, `world/LevelGenerator.ts`, `util/*`). This
  feature adds three numeric constants to `config/constants.ts` (no Phaser import) and edits two
  Phaser-coupled files (`entities/Tank.ts`, `scenes/GameScene.ts`) the verifier never imports — the
  pure/coupled enclosure is intact.
- AI randomness stays OFF the seeded pin: the in-tick wander/seek/aim rolls remain runtime `Math.random()`
  (the F4 contract), invisible to the determinism pin. The only seeded draw added is the cohort coin flip
  in `_spawnStep` on the EXISTING `stageRng` stream the spawn loop already advances — it does NOT touch
  `generateStage`/`LevelGenerator`, so the procedural-stage determinism + monotonicity gates are unaffected.
- No new tunable touches a verifier invariant: `tanks.ts` (the swept spec table), the four-types-distinct
  check, boss-HP monotonicity, and the currency-range guard are all unchanged. The new constants are plain
  AI feel scalars read only by coupled code (like the AI_* / LANE_* numbers already present).

## 6. i18n keys to add

NONE. Smarter AI is a pure behavior change with NO new user-facing text (no HUD label, menu entry, or
banner) — it surfaces only as enemy movement/firing behavior. So `src/i18n/en.ts` / `zh-CN.ts` need no
change, exactly like the ice-slide and steel-break feel features.
