# Ice-slide — make ICE tiles slippery on the Tank movement spine

## 1. Background / Intent

`tiles.ts` ships `TILE.ICE` (passableByTank, passableByBullet, NOT destructible) and `TileMap`
already draws an ICE rect tagged `tileKind = TILE.ICE` (a bodiless decoration — everything passes).
Both call it the seam "for the LATER low-friction feel". Today that seam is DEAD: a tank on ice
stops as instantly as on bare ground.

GOAL: when a tank's CENTER sits on an ICE tile, releasing the direction key keeps it GLIDING
~1 tile with momentum decay instead of stopping dead, and a turn is slippery (the new heading
takes a beat to win). CRITICAL invariants to preserve: the no-diagonal rule (never two velocity
components non-zero in one frame) and the lane-snap (defer the turn-time re-center WHILE sliding,
re-settle once stopped).

## 2. Key Decisions

1. **Single-axis glide only (KISS / YAGNI).** Ice momentum lives on the ONE axis the tank was last
   driving (`lastDriveAxis`). We carry a signed `glideVel` (px/s) along that axis. NO 2D velocity
   vector, NO diagonal drift — so the no-diagonal invariant stays STRUCTURAL: only the last-driven
   axis ever carries non-zero velocity, the cross axis is held at EXACTLY 0 exactly as today.

2. **The Tank samples the tile under its body via an injected query (SOLID, keeps purity).**
   `Tank.update` must not import TileMap (Phaser-coupled) nor re-implement grid math. The SCENE owns
   the tilemap, so GameScene injects a closure `tank.onSampleTile = (x, y) => tileKind` once at build
   time (a new optional field, like `onDeath`/`onDropFlag`). The scene's closure does the GRID→SCREEN
   inverse (`col = floor((x − PLAYFIELD_X)/TILE_SIZE)`, same for row) and reads `this.desc.tiles`
   (already used at GameScene:599). A null sampler ⇒ `update` behaves byte-identically to today
   (enemies/tests that don't wire it never glide — additive, zero-risk).

3. **`onIce` is read at the tank CENTER (the classic).** `update` calls
   `onSampleTile?.(body.center.x, body.center.y) === TILE.ICE`. Importing `TILE` into Tank.ts is
   fine — `tiles.ts` is PURE (no Phaser), so the existing pure/coupled split is untouched (Tank.ts
   already imports pure `constants.ts`/`tanks.ts`).

4. **Momentum model = a decay toward 0 when no key is held, on ice only (DRY constant).** Add ONE
   constant `ICE_FRICTION` to constants.ts: the per-second multiplicative retention of glide speed
   while coasting on ice (e.g. 0.88/frame-equivalent expressed as a per-second factor applied as
   `glideVel *= ICE_FRICTION ** dt`). Tuned so the tank coasts ~1 tile before `|glideVel|` drops
   under a small cutoff and snaps to 0. NO new "ice accel" constant (YAGNI) — driving onto ice still
   accelerates instantly to `moveSpeed` (only the RELEASE coasts; that is the readable classic feel).

5. **Drive step rewrite (the spine, step 3) — gated, behaviour-preserving OFF ice.** Replace the
   hard `setVelocity(...)` / `else setVelocity(0,0)` with:
   - **A key IS held on a drive axis** → set that axis to ±moveSpeed (as today) AND seed
     `glideVel = that signed speed`, `glideAxis = driveAxis`. (Off ice this is identical to today;
     on ice it just records momentum.)
   - **No key held** → if `onIce && |glideVel| > ICE_GLIDE_CUTOFF`: keep moving the `glideAxis` at
     `glideVel`, decay `glideVel *= ICE_FRICTION ** dt`; the cross axis stays 0 (no diagonal). Else
     `setVelocity(0,0)` and clear `glideVel` (the existing instant-stop — bare ground, AC).
   `ICE_GLIDE_CUTOFF` is a tiny px/s floor (a LOCAL render-free const in constants.ts beside
   ICE_FRICTION, DRY) below which we settle to rest so the tank doesn't creep forever.

6. **Slippery turns = defer the lane re-center while gliding; re-settle when stopped (AC).** The
   turn-time `_recenterCross` snap is the lane discipline. While `onIce` AND the tank is still
   carrying glide (post-release coast OR the same frame as a turn on ice), SKIP the snap (the surface
   is slippery — an instant lane snap would feel sticky). When the glide settles to 0 (cutoff reached)
   OR the tank leaves ice, run the SAME `_recenterCross` on the current heading's cross axis ONCE so
   the tank re-settles into its lane — reusing the existing helper verbatim (DRY, no second snap path).
   The no-diagonal invariant holds: the re-settle writes only `body.position[cross]`, velocity stays 0.

7. **Enemies do NOT glide this pass (YAGNI / scope).** Only the scene wires `onSampleTile` on the two
   PLAYER tanks (`_buildPlayer`); enemy build leaves it null, so enemies keep today's crisp AI grid
   movement (gliding enemy AI would fight the wander/seek re-decide — out of scope). The spine is the
   same; the feature is opt-in per tank via the injected sampler.

## 3. Files to touch

- **`src/config/constants.ts`** (PURE) — add `ICE_FRICTION` (per-second glide retention, 0<f<1) and
  `ICE_GLIDE_CUTOFF` (px/s settle floor) in the F-feature heavy-comment style, beside the tank-feel
  anchors (LANE_*). The single PURE owners (DRY). No Phaser import (purity preserved).

- **`src/entities/Tank.ts`** (Phaser-coupled) —
  - Import `TILE` from `../config/tiles.js` and `ICE_FRICTION`, `ICE_GLIDE_CUTOFF` from constants.
  - Add fields: `onSampleTile: ((x:number,y:number)=>number) | null` (default null, like `onDeath`);
    private `glideVel: number` (0) and `glideAxis: 'x'|'y'|null` (null).
  - In `update` step 3, implement Decision 5's gated drive (held → drive + seed glide; released →
    ice-coast-with-decay or instant stop). Sample `onIce` once at the top of step 3 via the center.
  - In step 4, gate the turn-time `_recenterCross` per Decision 6 (skip while sliding; re-settle once
    `glideVel` hits 0 or off ice).
  - Reset `glideVel = 0`, `glideAxis = null` in `respawnAt` and in the `!alive` early-return park
    (defensive — a corpse/respawn carries no momentum).

- **`src/scenes/GameScene.ts`** (Phaser-coupled) — in `_buildPlayer`, after constructing the tank,
  set `tank.onSampleTile = (x, y) => this._tileKindAt(x, y)`. Add ONE small private helper
  `_tileKindAt(x,y)` that does the GRID→SCREEN inverse and reads `this.desc.tiles[row][col]`
  (bounds-guarded → `TILE.EMPTY` off-grid), reusing the existing `desc.tiles`/`TILE` references
  already in this file. Enemy build (`_spawnEnemyAt`/boss) leaves the sampler null (no glide).

NO change to any PURE module beyond the additive constants. `LevelGenerator.ts`, `tiles.ts` (already
has ICE), and the verifier-imported set are otherwise untouched.

## 4. Acceptance criteria

1. A player tank whose center is on an ICE tile, on releasing all direction keys, KEEPS moving along
   its last drive axis and coasts ~1 tile before stopping (momentum decay), instead of stopping dead.
2. On bare ground (EMPTY/TREES) releasing the key stops the tank INSTANTLY — byte-identical to today.
3. The no-diagonal invariant holds at all times on ice: at most one velocity component is ever
   non-zero in a frame (verified by inspection of the gated drive — the cross axis is never written).
4. While gliding the lane-snap is DEFERRED; once the glide settles (or the tank leaves ice) the tank
   re-settles into its corridor lane via the existing `_recenterCross` (no permanent lane drift).
5. Enemies are unaffected (their `onSampleTile` is null → the existing instant-stop path runs).
6. A respawn / death clears any carried glide (no momentum survives across lives).
7. `npm run typecheck`, `npm run verify`, and `npm run build` all stay green.

## 5. How `npm run verify` stays green

- The verifier node-imports ONLY the PURE modules (`config/*`, `world/LevelGenerator.ts`, `util/*`).
  This feature adds only two numeric constants to `config/constants.ts` (no Phaser import) and edits
  two Phaser-coupled files (`entities/Tank.ts`, `scenes/GameScene.ts`) the verifier never imports — so
  the pure/coupled enclosure is intact. Tank.ts imports `tiles.ts`, which is itself PURE — no Phaser
  reaches a verifier-imported file.
- No RNG and no stage-generation change: ICE placement, the stage grid, and `generateStage` are
  untouched, so the determinism pin + the procedural-stage monotonicity gate are byte-unaffected.
- The new constants are plain feel scalars read only by the coupled entity; no verifier invariant
  (four-types-distinct, boss-HP monotonicity, currency range) references them.

## 6. i18n keys to add

NONE. Ice-slide is a pure movement/feel mechanic with NO new user-facing text (no HUD label, menu
entry, or banner) — it surfaces only as tank momentum on ice. So `src/i18n/en.ts` / `zh-CN.ts` need
no change, exactly like the steel-break feel feature. (If a later feature adds an on-screen "ICE"
indicator, that string — and only then — is added to BOTH locale files via `t()`.)
