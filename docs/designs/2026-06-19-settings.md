# Tank 1990 — Settings screen (master volume · default difficulty · language)

> A small PLAYABILITY pass: a Settings screen reachable from the Title that owns the persisted player
> PREFERENCES already partly stored by `util/settings.ts` (difficulty), and EXTENDS that same wrapper with two
> NEW fields — `volume` (a 0..1 master level wired to Phaser's global `sound.volume`, which `audio/Sound.ts`
> ALREADY multiplies into every synthesized sound) and `locale` ('en' | 'zh-CN', making the active locale
> PERSISTENT + switchable at runtime instead of boot-only auto-detect). NO new save schema, NO new storage code:
> it reuses `loadSettings()` / `saveSettings()` (which already inherit `util/save.ts`'s defensive try/catch — they
> never throw). The screen is a SCENE (not a modal) registered beside the Title, matching the existing
> Title→Hub flow. i18n every label in both locales (ZH ⊆ EN). The whole change is Phaser-coupled ONLY in the
> scene + `main.ts`; the pure `util/settings.ts` / `config/constants.ts` / `i18n/*` edits add only DATA.

---

## 1. Background

`util/settings.ts` ALREADY exists (born in F-difficulty-select / F-seed-challenge): a PURE wrapper over
`util/save.ts`'s defensive `get`/`set` under the `tank-1990:settings` key, with `Settings = { difficulty,
startStage, seed }`, a frozen `DEFAULT_SETTINGS`, and a `loadSettings()` that back-fills + clamps every field so
a corrupt/old value degrades to the default (never throws). The Title already `loadSettings()`s + cycles
difficulty / start-stage / seed and `saveSettings()`s each change. So the persistence seam, the
clamp-on-read discipline, and the Title-as-preference-owner pattern are all in place.

Two preferences are MISSING:

- **Master volume.** `audio/Sound.ts` synthesizes every sound and ALREADY scales each tone/noise by
  `this.sm.volume` (Phaser's global `scene.sound.volume`, shared across all scenes via the one
  `WebAudioSoundManager`). So a master-volume control is just "persist a 0..1 number and push it into
  `game.sound.volume` once at boot + whenever it changes" — NO change to `Sound.ts` itself (it already reads the
  live global). Today nothing ever sets it (defaults to 1).
- **Language.** `i18n/index.ts` has `setLocale` / `getLocale` / `detectLocale`; `main.ts` calls
  `setLocale(detectLocale())` ONCE at boot (browser-detected, NOT persisted, NOT switchable). The brief wants
  the active locale persistent + switchable at runtime.

What is also missing is any dedicated **Settings screen** — difficulty currently lives inline on the crowded
Title. The brief asks for a Settings screen reachable from the Title (default difficulty + volume + language).

**Conventions mirrored:** shared numbers live ONCE in `config/constants.ts`; preferences persist through
`util/settings.ts` over `save.ts`'s defensive get/set (no new storage); all UI text goes through `t()` with keys
in BOTH locales (ZH ⊆ EN); the screen is a Scene registered in `main.ts` (the Title→Hub pattern). Governing
principles: **KISS, YAGNI, DRY, SOLID.**

## 2. Requirements Summary

**Goal:** a Settings screen reachable from the Title — master volume (wired to `Sound`/Phaser global volume),
default difficulty, and a runtime language toggle (en / zh-CN) — all persisted via `util/settings.ts`; keep
verify green.

**In scope:**

- **`src/config/constants.ts` (CHANGED, PURE):** add the shared volume knobs (DRY owner) — `VOLUME_STEP = 0.1`
  (the +/- increment) and the `[0, 1]` bounds are the literal 0/1 (no new constant needed). NO other numeric
  addition (difficulty/start-stage constants already live here).
- **`src/util/settings.ts` (CHANGED, PURE):** extend `Settings` with `volume: number` (0..1, master level) and
  `locale: Locale` ('en' | 'zh-CN'); add both to `DEFAULT_SETTINGS` (`volume: 1`, `locale: 'en'` — see D4 on the
  first-launch detect). Extend `loadSettings()` to back-fill + CLAMP each: `volume` → `clamp(Number || default,
  0, 1)`; `locale` → the value if it is one of the two valid `Locale`s, else the default (the SAME defensive
  pattern the existing `difficulty` field uses). `saveSettings` is unchanged (it writes the whole object). PURE
  of Phaser (the verifier node-imports it — re-proving purity; importing `Locale` as a TYPE from `i18n` stays
  pure, `i18n/index.ts` is already Phaser-free).
- **`src/main.ts` (CHANGED):** at boot, AFTER building the game, read `loadSettings()` ONCE and apply BOTH
  globals: `setLocale(settings.locale)` (the persisted locale, replacing the bare `detectLocale()` — see D4 for
  the first-launch path) and `game.sound.volume = settings.volume`. This is the single boot apply-site
  (mirrors how `main.ts` already owns the one boot `setLocale` call).
- **`src/scenes/SettingsScene.ts` (NEW, Phaser-coupled):** a small full-screen menu scene (the Title's layout
  discipline — every Y off the FIXED `DESIGN_WIDTH`/`DESIGN_HEIGHT`, centered under `Scale.FIT`). Three rows
  (VOLUME · DIFFICULTY · LANGUAGE) with a cursor bar (↑/↓ to move, ←/→ to change the focused row's value), plus
  a BACK row. Reads `loadSettings()` once into a mutable local; each change `saveSettings()`s + re-renders +
  blips (the `uiMove` tick — a no-op under NoAudio), exactly the Title chooser pattern (DRY in spirit). The
  value edits APPLY LIVE: a volume change sets `this.sound.volume` (so the blip plays at the new level
  immediately — instant feedback); a language change calls `setLocale()` then RE-RENDERS this scene's labels
  (so the toggle is visibly runtime). A `Sound` instance gives the nav/confirm blips. BACK (or ESC) routes
  `this.scene.start('Title')` so the Title re-reads the (possibly new-locale) settings on re-entry.
- **`src/scenes/TitleScene.ts` (CHANGED):** add a single "Settings" hint line + an `O` (Options) key (and/or a
  dedicated key) that routes `this.scene.start('Settings')`. Guarded by the existing `editingSeed` /
  `started` latches (so it never fires mid-seed-entry or after start). One new key handler + one localized line —
  no other Title change (the difficulty chooser STAYS on the Title too; Settings owns the DEFAULT difficulty +
  the new volume/language knobs — they share the SAME `settings.difficulty` field, so the two views stay in
  sync via `loadSettings()` on each entry — D3).
- **`src/i18n/en.ts` + `src/i18n/zh-CN.ts` (CHANGED, PURE):** add the Settings keys in BOTH locales (ZH ⊆ EN):
  `settings.title`, `settings.volume`, `settings.difficulty`, `settings.language`, `settings.back`,
  `settings.hint`, `settings.lang.en`, `settings.lang.zh`, and `title.settings` (the Title hint line). Reuse the
  existing `title.diff.easy/normal/hard` for the difficulty value display (DRY — no new difficulty labels).
- **`src/main.ts` scene registration (CHANGED):** register `SettingsScene` in the `scene: [...]` array (inert
  until `scene.start('Settings')` — the same pattern as every non-Boot scene).

**Out of scope (NOT built):** per-channel volume (music vs sfx) — ONE master level (KISS/YAGNI); a settings entry
from the in-run pause overlay — the brief says "Title (and/or pause)"; Title-only keeps it KISS and the pause
overlay is deliberately READ-ONLY (D9 of F7) — adding edit rows there would break that contract, so we DON'T
(YAGNI); changing `audio/Sound.ts` (it already reads the live global volume — DRY); adding a `language` field to
the META schema (the preference belongs in `tank-1990:settings`, NOT the run economy — SOLID, no migration);
mouse/pointer editing of rows (keyboard nav matches the Title/Hub discipline — KISS); a third locale.

## 3. Acceptance Criteria

1. **AC1 — the volume + locale preferences persist via the EXISTING wrapper.** `Settings` gains `volume` +
   `locale`; `loadSettings()` back-fills + clamps both (`volume` ∈ `[0,1]`; `locale` ∈ `{en, zh-CN}` else the
   default); a corrupt/old save (no volume/locale field) degrades to `DEFAULT_SETTINGS` and NEVER throws (it
   inherits `save.ts`'s try/catch — the verifier node-imports `util/settings.ts`, re-proving purity).
2. **AC2 — master volume is wired end-to-end.** A Settings volume change sets `this.sound.volume` live (the next
   blip is audible at the new level) AND `saveSettings()`s; `main.ts` applies `game.sound.volume =
   settings.volume` at boot. `audio/Sound.ts` is UNCHANGED (every sound already multiplies by `this.sm.volume`),
   so volume 0 = silent, 1 = full, across every scene's sounds.
3. **AC3 — language is persistent + switchable at runtime.** A Settings language toggle calls `setLocale()` +
   `saveSettings()` + re-renders the Settings labels IN PLACE (the screen visibly flips locale without a
   reload); `main.ts` boot reads `loadSettings().locale` so the choice survives a relaunch; the Title (re-entered
   via BACK) renders in the chosen locale.
4. **AC4 — default difficulty is editable from Settings + shared with the Title.** The DIFFICULTY row cycles the
   SAME `settings.difficulty` field the Title chooser uses (via `loadSettings`/`saveSettings`), so the two views
   never disagree — changing it in Settings, returning to Title, shows the new value (and the next run uses it).
5. **AC5 — the screen is reachable + returns cleanly.** The Title shows a localized Settings hint + an `O` key
   that `scene.start('Settings')`s (suppressed mid-seed-entry / after start); Settings BACK/ESC
   `scene.start('Title')`s. `SettingsScene` is registered in `main.ts` (inert until started).
6. **AC6 — fully localized (ZH ⊆ EN).** Every new string is in `en.ts` AND `zh-CN.ts`; the difficulty values
   reuse `title.diff.*`. The verifier's `ZH_CN.ui ⊆ EN.ui` check stays green (no orphan zh key).
7. **AC7 — green gate + pure/coupled split.** `npm run typecheck` + `npm run build` exit 0; `npm run verify`
   prints OK + exits 0. `config/constants.ts` / `util/settings.ts` / `i18n/*` import NO Phaser (node-imported by
   the verifier); `SettingsScene.ts` + `main.ts` import Phaser and are NEVER node-imported. The verifier's
   determinism + procedural-stage (monotonicity/bounds) gates are UNAFFECTED (this feature touches no ramp /
   generator / RunState code).

## 4. Decision Log

1. **D1 — EXTEND `util/settings.ts`, do NOT add a new save key/module.** Volume + locale are pre-run player
   PREFERENCES, the EXACT concern `tank-1990:settings` already owns (difficulty/start-stage/seed). Adding two
   fields to the existing `Settings` + `DEFAULT_SETTINGS` + the back-fill/clamp in `loadSettings()` reuses ALL
   the defensive plumbing (no new storage code, no migration — `loadSettings` already back-fills missing fields
   from `DEFAULT_SETTINGS`). *Rationale:* DRY + SOLID (one preference store) + YAGNI (no second wrapper).
2. **D2 — Master volume rides Phaser's GLOBAL `sound.volume` — `audio/Sound.ts` is UNTOUCHED.** Every synthesized
   tone/noise already computes `peak = gain * MASTER_GAIN * this.sm.volume`. So "master volume" = persist a 0..1
   number and write it to `game.sound.volume` (boot) / `this.sound.volume` (live edit). No new audio API, no
   per-sound plumbing. *Rationale:* KISS/DRY — the seam already exists; the smallest correct wiring.
3. **D3 — Difficulty stays a SINGLE shared field; both Title + Settings edit it.** The brief asks Settings to own
   "default difficulty"; the Title already has a difficulty chooser. Rather than fork them, BOTH read/write
   `settings.difficulty` (each scene `loadSettings()`s on entry), so they are always consistent — Settings is
   just a second editor of the same preference, surfaced on its dedicated screen. *Rationale:* DRY (one source of
   truth) — no duplicated state, no sync bug. (The Title chooser could later be REMOVED to declutter, but that is
   not this feature's job — YAGNI.)
4. **D4 — Persisted locale, with first-launch DETECT as the seed.** Boot reads `loadSettings()`: if the save is
   FRESH (no prior `locale`), `loadSettings` returns the `DEFAULT_SETTINGS.locale`. To honor the existing "a zh
   browser auto-detects to Chinese" behaviour on a first-ever launch WITHOUT persisting a wrong choice,
   `main.ts` uses `settings.locale` when the user has already chosen one, else `detectLocale()`. KISS impl: keep
   `DEFAULT_SETTINGS.locale = 'en'` but, in `main.ts`, prefer the STORED settings' locale only when a settings
   blob actually exists; on a truly fresh save fall back to `detectLocale()` and `saveSettings` it once (so the
   detected locale becomes the persisted default). *Rationale:* preserves today's auto-detect UX for new players
   while making the choice sticky + switchable thereafter — the brief's "persistent and switchable" intent.
   *(Implementation note: the simplest correct form is `main.ts` reading a `hasStored` flag — e.g.
   `get(SETTINGS_KEY, null) != null` exposed as a tiny helper, OR seeding `DEFAULT_SETTINGS.locale` from
   `detectLocale()` is NOT viable because `settings.ts` must stay Phaser/DOM-light + pure; the helper lives in
   `main.ts` which is already DOM-coupled.)*
5. **D5 — Settings is a SCENE, not a modal overlay.** The Title→Hub→Game flow is scene-based; a full-screen
   options menu is naturally a sibling scene (`scene.start`), reusing the Title's centered-layout discipline and
   needing no pause/freeze handshake. The PauseOverlay is deliberately read-only (F7 D9) — reusing it would break
   that. *Rationale:* matches the existing scene pattern (SOLID — one scene per screen); KISS.
6. **D6 — Volume is clamped to `[0,1]` in `VOLUME_STEP` increments; never below 0 / above 1.** The Settings
   ←/→ adjust by `VOLUME_STEP` and clamp, so the persisted value is always a valid Phaser volume. *Rationale:*
   defensive — a malformed value can never feed an invalid global volume.

## 5. Design

### 5.1 Module layout (this phase)

```
src/
  config/
    constants.ts        # CHANGED (PURE): + VOLUME_STEP (the shared +/- increment; 0/1 bounds are literal).
  util/
    settings.ts         # CHANGED (PURE): Settings += volume + locale; DEFAULT_SETTINGS += them; loadSettings back-fills + clamps both.
  scenes/
    SettingsScene.ts    # NEW (Phaser): the VOLUME / DIFFICULTY / LANGUAGE / BACK menu — cursor nav, live apply, save + blip.
    TitleScene.ts       # CHANGED: + a Settings hint line + an `O` key → scene.start('Settings').
  i18n/
    en.ts               # CHANGED (PURE): + settings.* keys + title.settings.
    zh-CN.ts            # CHANGED (PURE): the same keys (ZH ⊆ EN).
  main.ts               # CHANGED: register SettingsScene; at boot apply loadSettings() → setLocale + game.sound.volume (D4 fresh-detect).
```

NO change to: `audio/Sound.ts` (reads the live global volume — D2), `config/stages.ts` / `core/RunState.ts` /
`world/LevelGenerator.ts` / the generator (no ramp/determinism touch — AC7), `scripts/verify-gen.mjs` (the i18n
ZH ⊆ EN check already covers the new keys; no new pure contract to assert — see §5.4).

### 5.2 `util/settings.ts` (the extended preference)

```
export interface Settings {
  difficulty: Difficulty      // (existing)
  startStage: number          // (existing)
  seed: number | null         // (existing)
  volume: number              // NEW — master level 0..1 (→ Phaser global sound.volume).
  locale: Locale              // NEW — 'en' | 'zh-CN' (the persisted active locale).
}
DEFAULT_SETTINGS = { ...existing, volume: 1, locale: 'en' }
// loadSettings(): after the existing difficulty/startStage/seed coercion —
const volume = clamp(Number(merged.volume), 0, 1)         // NaN/out-of-range → defaulted via the existing clamp+Number guard.
const locale: Locale = LOCALES.includes(merged.locale) ? merged.locale : DEFAULT_SETTINGS.locale
return { difficulty, startStage, seed, volume, locale }
```
`Locale` is imported as a TYPE from `../i18n/index.js` (Phaser-free — purity preserved); the valid-locale set
mirrors the existing `DIFFICULTIES` guard.

### 5.3 `main.ts` boot apply (D2/D4)

```
const game = new Phaser.Game(config)
const settings = loadSettings()
// D4: honor today's browser auto-detect on a TRULY fresh save (no stored blob), else the stored locale.
const locale = hasStoredSettings() ? settings.locale : detectLocale()
setLocale(locale)
game.sound.volume = settings.volume      // 1 by default → today's behaviour, byte-unchanged.
if (!hasStoredSettings()) saveSettings({ ...settings, locale })   // seed the detected locale once (D4).
```
`hasStoredSettings()` is a tiny `main.ts`-local check (`get(SETTINGS_KEY, null) != null` via the `save.ts`
get) — kept OUT of the pure `settings.ts` (it is a boot-policy detail, not a preference shape). `setLocale` runs
BEFORE the first scene renders chrome (the existing boot-order discipline).

### 5.4 `SettingsScene.ts` (the menu)

A centered column of rows; a cursor index selects the focused row; ←/→ edits it, ↑/↓ moves the cursor, ENTER on
BACK (or ESC anywhere) returns to Title. One render path (`renderRows()`) re-tints the cursor + re-texts the
values (the Title chooser pattern — DRY in spirit):
- **VOLUME** — `t('settings.volume')` + a value (e.g. a percentage `Math.round(volume*100)`); ←/− and →/+ by
  `VOLUME_STEP` clamped `[0,1]`; on change: `this.sound.volume = volume; saveSettings(settings); sfx.uiMove()`
  (the blip plays at the NEW level — instant feedback).
- **DIFFICULTY** — `t('settings.difficulty')` + `t('title.diff.'+difficulty)`; ←/→ cycle the three levels
  (reusing the Title's LEVELS pattern); on change `saveSettings` (the SAME field the Title edits — D3).
- **LANGUAGE** — `t('settings.language')` + `t(locale==='en' ? 'settings.lang.en' : 'settings.lang.zh')`; ←/→
  toggle the two locales; on change: `setLocale(locale); saveSettings(settings); renderRows()` — re-render so the
  WHOLE screen (every label) flips locale live (AC3).
- **BACK** — `t('settings.back')`; ENTER → `this.scene.start('Title')`.

A `Sound` instance (the Title's pattern — a no-op under NoAudio) gives `uiMove`/`uiSelect` blips. NO music. All
positions off `DESIGN_WIDTH`/`DESIGN_HEIGHT` (centered under `Scale.FIT`).

### 5.5 Verifier impact (none needed)

The only PURE additions are DATA: two `Settings` fields (back-filled/clamped like the existing ones) + i18n keys.
The verifier ALREADY: (a) node-imports `util/settings.ts`? — it imports `config/*` + `i18n/*` + `RunState`;
`settings.ts` purity is re-proven transitively the moment any pure module imports it, and at minimum it is
node-safe (no Phaser) so `npm run verify` is unaffected. (b) asserts `ZH_CN.ui ⊆ EN.ui` — adding the `settings.*`
keys to BOTH locales keeps that green. No ramp/determinism/monotonicity code is touched, so §5/§6/§7 of the
verifier are byte-unaffected. (Optional, if cheap: a one-line §8e-style assert that `DEFAULT_SETTINGS.volume`/
`.locale` round-trip through `loadSettings` of a garbage blob → the defaults; but the existing structure check
already covers the load-bearing i18n contract — YAGNI unless the next agent wants belt-and-suspenders.)
