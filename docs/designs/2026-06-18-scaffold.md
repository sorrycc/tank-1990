# Tank 1990 — F0 Scaffold (project skeleton)

> Design doc for **F0 Scaffold**, the first feature of Tank 1990 (a faithful Battle City /
> 坦克大战 clone). Format mirrors the read-only reference `dead-cell` design docs EXACTLY:
> Background → Requirements Summary → Acceptance Criteria → Decision Log → Design → Files →
> Verification. This phase stands up an EMPTY repo into a booting Phaser+Vite+TypeScript
> skeleton with all scene stubs, the seeded RNG, defensive save helpers, and a green
> `typecheck` / `build` / `verify` — the foundation every later feature builds on. No gameplay
> yet (Decision 4 — YAGNI: stubs only).

---

## 1. Background

Build, from an EMPTY repo, a 2D **top-down grid** tank shooter in the spirit of **Battle City
(Tank 1990)**: defend the **eagle** base (bottom-center, walled in brick) and clear each stage
of enemy tanks across a classic **13×13** tile grid. The full game (delivered across later
features F1…Fn) is a FAITHFUL CLASSIC core — terrain tiles (empty / brick / steel / water /
trees / ice), the 6 classic power-ups, 4 classic enemy types, 2-player local co-op, a boss
every 5th stage, ENDLESS escalating difficulty, and a persistent META HUB for permanent
per-player upgrades. There is **NO Victory scene** — the game is endless; a run ends only when
the eagle is destroyed or all lives are spent.

This F0 feature delivers ONLY the scaffold: a project that installs clean, boots six scenes,
reaches Boot → Title → Hub → Game, and is green on `typecheck` / `build` / `verify`. It carries
NO gameplay — just the skeleton + shared constants + pure utilities the rest of the build
stands on.

**Stack & shape (LOCKED, pre-decided):** **Phaser 3 + Vite**, ES modules (`"type":"module"`),
TypeScript, **programmer-art PRIMITIVES ONLY** (colored rectangles / Phaser `Graphics` +
generated textures — NO external sprite / font / audio assets; runs offline + from `file://`).
The state machine is expressed as Phaser **Scenes**: Boot → Title → Hub → Game (+ a PARALLEL
HUD overlay scene) → GameOver. **No Victory scene** (endless). Fixed design resolution
**1280×720**, `Scale.FIT` letterbox + `autoCenter` `CENTER_BOTH`. Governing conventions: **KISS,
YAGNI, DRY, SOLID** (user global instructions).

**Conventions mirrored from `dead-cell` (read-only reference, NEVER modified):** layered modules
(`scenes/ core/ world/ entities/ combat/ config/ effects/ audio/ i18n/ util/`); seeded
determinism via `util/rng.ts` `mulberry32` (copied BYTE-IDENTICAL) for ALL procedural
generation; the PURE/COUPLED split — `config/*` (and later `world/LevelGenerator`) import
NOTHING from Phaser so `scripts/verify-gen.mjs` can import them headlessly under plain node,
while Phaser-coupled code (scenes, entities) is NEVER imported by the verifier; defensive
`localStorage` in `util/save.ts` (every access try/catch, never throws); shared numbers live
ONCE in `src/config/constants.ts`; `tsconfig.json` with `useDefineForClassFields:false`; heavy,
intent-revealing comments that cite the design section + Acceptance Criteria + Decision numbers.

## 3. Acceptance Criteria

> All testable. §8 maps each AC to a `typecheck` / `build` / `verify` check or a code-presence
> grep.

1. **AC1 — Clean install.** `npm install` completes with no errors; only `phaser` (runtime) +
   `vite` / `typescript` / `tsx` (dev) are declared; `package.json` has `"type":"module"`.
2. **AC2 — Typecheck green.** `npm run typecheck` (`tsc --noEmit`, strict) exits 0.
3. **AC3 — Build emits dist/.** `npm run build` (`vite build`) exits 0 and writes a `dist/`
   with an `index.html` + a hashed JS bundle.
4. **AC4 — Six scenes registered.** `src/main.ts` constructs ONE `Phaser.Game` whose `scene`
   array is EXACTLY `[BootScene, TitleScene, HubScene, GameScene, HUDScene, GameOverScene]` (no
   Victory scene); `Scale.FIT` at `DESIGN_WIDTH×DESIGN_HEIGHT`, `autoCenter CENTER_BOTH`.
5. **AC5 — Top-down, no gravity.** Arcade physics is enabled in the game config but NO `gravity`
   key is set (top-down); `constants.ts` exports NO `GRAVITY`.
6. **AC6 — Scene flow reachable.** Boot auto-starts → `scene.start('Title')`; Title → `'Hub'`
   on a key OR pointer; Hub → `'Game'` on START; Game renders a placeholder rect; GameOver →
   `'Title'`. HUD is a parallel overlay stub. Each scene's transition target exists in the
   registered set.
7. **AC7 — RNG byte-identical.** `src/util/rng.ts` exports `mulberry32` + `range`; the
   `mulberry32` body is byte-identical to the reference, so the same seed yields the same
   sequence (the verifier pins it).
8. **AC8 — Save defensive + meta schema.** `src/util/save.ts` exports defensive `get` / `set`
   (every access try/catch; never throws) and `DEFAULT_META` / `loadMeta` / `saveMeta` over the
   schema `{ currency:number, upgrades:{'1':…,'2':…}, bestScore:number, bestStage:number }`;
   `loadMeta` spread-backfills missing keys and CLONES the mutable containers (no aliasing the
   frozen default).
9. **AC9 — Verify green.** `npm run verify` (`tsx scripts/verify-gen.mjs`) imports the PURE
   `rng.ts`, `config/constants.ts`, AND `util/save.ts`, asserts `mulberry32` determinism (two
   instances of one seed deep-equal; a known seed matches a pinned prefix), prints `OK`, and exits 0.
10. **AC10 — Pure/coupled split preserved + EXECUTED.** `config/constants.ts`, `util/rng.ts`,
    `util/save.ts` import NOTHING from Phaser (node-importable); scene stubs + `main.ts` are the only
    Phaser-coupled files and are NEVER imported by the verifier. This is made EXECUTABLE (not just
    grep-asserted): the verifier ACTUALLY imports all three pure modules so a successful `npm run
    verify` re-proves their node-importability/purity, and asserts a trivial invariant in EACH —
    `DESIGN_WIDTH === 1280` (constants), the `mulberry32` pin (rng), and a `saveMeta`/`loadMeta`
    round-trip whose `upgrades['1']`/`upgrades['2']` are NOT the frozen-`DEFAULT_META` reference
    (save — also exercising the AC8 clone-no-alias contract in the harness).
11. **AC11 — Offline / programmer-art.** No scene issues a network `load.*` call; `index.html`
    loads no external fonts/assets; `CREDITS.md` documents the programmer-art-only constraint.

## 4. Decision Log

1. **D1 — Mirror the reference stack & tooling verbatim.** Copy the reference's `package.json`
   shape (scripts, dep/devDep split), `tsconfig.json` (incl. `useDefineForClassFields:false`),
   `vite.config.js` (`base:'./'`), and `index.html` structure, adapting only names/copy.
   *Rationale:* the project brief mandates mirroring `dead-cell` EXACTLY; reusing a proven config
   is KISS/DRY and removes a whole class of setup bugs. `base:'./'` keeps the build runnable from
   any sub-path or `file://` (offline constraint). `useDefineForClassFields:false` keeps
   constructor-assignment semantics so type-only field declarations have ZERO runtime effect.
2. **D2 — Six scenes, no Victory.** Register `[Boot, Title, Hub, Game, HUD, GameOver]` only.
   *Rationale:* the game is ENDLESS (locked decision) — a run ends only on eagle-death / lives
   spent → GameOver. A Victory scene would be dead code (YAGNI). This is the ONE deliberate
   divergence from the reference's seven-scene set, and it is required by the locked design.
3. **D3 — Arcade physics ON, gravity OFF (top-down).** Enable Arcade in the game config but set
   NO `gravity`; export NO `GRAVITY` constant. *Rationale:* Battle City is top-down — tanks move
   on a grid, bullets travel straight, nothing falls. Enabling Arcade now (so GameScene can opt
   bodies in later) while omitting gravity matches the top-down model and avoids a global gravity
   world the menu/overlay scenes would have to fight (SOLID — per-scene concerns stay isolated).
   This intentionally diverges from the reference's `GRAVITY` constant, which a platformer needs
   and a top-down grid game does not.
4. **D4 — Stubs only; no speculative gameplay (YAGNI).** Scenes are minimal: Boot hands off,
   Title/Hub/GameOver show a heading + a transition control, Game draws ONE placeholder rect, HUD
   is an empty parallel overlay. *Rationale:* F0 is the skeleton; entities, the generator, input,
   power-ups, the FSM, and the upgrade trees each land in their own later feature with their own
   design doc. Building any of them now would be speculative and would contradict the
   one-feature-per-doc convention.
5. **D5 — `mulberry32` copied BYTE-IDENTICAL.** Copy `mulberry32` + `range` verbatim from the
   reference's `rng.ts`; adapt only the leading comment. *Rationale:* the locked decisions require
   byte-identical copy so seeds are cross-compatible and the verifier can pin EXACT output
   sequences. The PRNG is the determinism foundation for the F2 seeded stage generator. (The
   reference's extra `dailySeed` is OMITTED — Tank 1990 has no daily-challenge contract; YAGNI.)
6. **D6 — Defensive save + a 2-player meta schema, owned ONCE.** Keep the reference's defensive
   `get`/`set` (try/catch everywhere, never throws) and layer a typed `meta` wrapper, but with
   Tank 1990's OWN schema: `{ currency:number, upgrades:{'1':…,'2':…}, bestScore:number,
   bestStage:number }`. *Rationale:* the locked meta-hub decision is a SHARED currency bank with
   PER-PLAYER upgrade trees (P1 | P2 columns) and persisted `bestScore` + `bestStage`. Modelling
   `upgrades` as `{'1','2'}` from the start means `applyUpgrades(slot)` (a later feature) folds
   exactly one player's tree with no schema migration. `loadMeta` spread-backfills missing keys
   and DEEP-clones the per-player container maps so a back-filled save never aliases the frozen
   `DEFAULT_META` (the exact cross-instance-leak fix the reference documents). Owning the schema in
   one place is DRY; the verifier stays Phaser-free because `save.ts` imports nothing from Phaser.
7. **D7 — Grid/tank/bullet constants centralized in `constants.ts` (PURE).** Put the 13×13 grid,
   tile + sub-cell sizes, playfield offset + HUD-panel width, tank/bullet speeds, fire cooldown,
   max player bullets, start lives, enemies-per-stage, max concurrent enemies, and
   boss-stage-every into the single PURE `constants.ts`. *Rationale:* more than one site needs
   these (main sizing, GameScene later, the F2 generator, the HUD) — owning them ONCE prevents
   drift (DRY). Keeping `constants.ts` Phaser-free preserves the pure/coupled split so the F2
   generator + verifier can import the grid math headlessly (the whole reason the reference keeps
   `config/*` pure).
8. **D8 — `UI_FONT` with a CJK fallback chain now (cheap i18n-readiness).** Export the reference's
   `UI_FONT` (`'monospace, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif'`).
   *Rationale:* the user reads zh-CN and a full i18n layer arrives in F1; every text site uses this
   ONE constant so CJK glyphs render (no tofu) without bundling a font (programmer-art constraint).
   Establishing it in F0 costs one line and prevents a later sweep of bare-`'monospace'` sites.
9. **D9 — Verifier is a determinism + purity STUB (F2 fills in the stage sweep).**
   `scripts/verify-gen.mjs` imports the pure `rng.ts`, `config/constants.ts`, AND `util/save.ts`,
   asserts determinism + one trivial invariant per module, prints `OK`, exits 0; on any failure it
   exits non-zero. *Rationale:* the real quality gate is the F2 seeded-stage sweep — but `npm run
   verify` must be GREEN now (locked AC). Importing all THREE pure modules (not just `rng.ts`) makes
   AC10's pure/coupled-split claim EXECUTABLE rather than aspirational: a Phaser import in any of them
   would throw under node, so a green `verify` is the independent proof of their purity (the
   reference's stance — its harness likewise imports every pure module it asserts on). The cost is one
   import + one cheap assert each: `DESIGN_WIDTH === 1280` for `constants.ts`, and a `saveMeta`/
   `loadMeta` round-trip for `save.ts` that ALSO exercises the AC8 clone-no-alias contract in the
   harness (see D9a). The script imports NO Phaser-coupled module (importing a scene would throw under
   node), so it is an independent proof, not self-certification — exactly the reference's stance.
9a. **D9a — The `save.ts` invariant exercises the AC8 clone-no-alias contract.** The verifier's
   `save.ts` assertion is NOT a bare smoke import: it round-trips `DEFAULT_META` through
   `saveMeta(loadMeta())` (defensive `localStorage` is absent under node, so `loadMeta` degrades to
   the spread-backfilled default — never throws, AC8) and asserts the loaded shape is stable
   (`currency`/`bestScore`/`bestStage` are `0`, `upgrades` has keys `'1'`+`'2'`) AND that the cloned
   `upgrades['1']`/`upgrades['2']` are NOT the SAME object reference as `DEFAULT_META.upgrades['1']`/
   `['2']` (the clone-no-alias guarantee D6 documents). *Rationale:* this proves in the HARNESS — not
   only by reading code — that a back-filled save owns its own per-player containers, so a later
   `buy()` can't mutate the frozen default (the cross-instance-leak the reference's clone fixes).
   Since `save.ts` is already pure + node-importable in F0, this is the cheap, convention-correct way
   to make AC10 executable while pinning the AC8 contract.
10. **D10 — `.js` import specifiers in `.ts` source.** Source imports use `./foo.js` even though the
    files are `.ts` (e.g. `import { mulberry32 } from '../util/rng.js'`). *Rationale:* this is the
    reference's convention under `moduleResolution:"bundler"` + ES modules; it lets Vite resolve in
    the browser AND lets the node-run verifier import `../src/util/rng.ts` via the same `.js`
    specifier through `tsx`. Matching it keeps F0 byte-consistent with how later features import.
11. **D11 — DEV-flag typed via the reference's inline cast (NOT `vite/client`).** See §5.3: guard the
    DEV `window.__game` branch with `(import.meta as ImportMeta & { env?: { DEV?: boolean } }).env?…`,
    copied verbatim from the reference, instead of a bare `import.meta.env.DEV` (which is untyped
    under strict `tsc --noEmit` with no `vite/client` reference, and would make AC2 red). *Rationale:*
    keeps `tsconfig.json` byte-identical to the reference (no `types`/triple-slash divergence — D1),
    needs no extra typecheck-visible type dep, and widens `ImportMeta` only at this one call site
    (SOLID). This is the explicit pin the green-gate requires.

### 5.2 Key types & constants

**`src/config/constants.ts`** (PURE — no Phaser import). All values are placeholders chosen to
make the 13×13 playfield + side HUD fit 1280×720 cleanly; later features tune feel but keep the
same NAMES (DRY anchors):

- `DESIGN_WIDTH = 1280`, `DESIGN_HEIGHT = 720`.
- `UI_FONT` — the CJK-fallback stack (D8).
- Grid: `GRID_COLS = 13`, `GRID_ROWS = 13`, `TILE_SIZE = 48` (13×48 = 624 px square playfield,
  fits 720 height with margin), `SUB_CELLS = 2` (each brick tile = 2×2 = 4 destructible
  sub-cells — the classic), `SUB_CELL_SIZE = TILE_SIZE / SUB_CELLS`.
- Layout: `PLAYFIELD_X` / `PLAYFIELD_Y` (top-left of the centered square playfield),
  `HUD_PANEL_WIDTH` (right-side panel like the original). Derived from `DESIGN_*`, `GRID_*`,
  `TILE_SIZE` so the single owner stays consistent.
- Tank/bullet: `TANK_SPEED` (px/s), `BULLET_SPEED` (px/s), `FIRE_COOLDOWN` (s),
  `MAX_PLAYER_BULLETS` (per player), `START_LIVES`.
- Stage: `ENEMIES_PER_STAGE = 20`, `MAX_CONCURRENT_ENEMIES = 4`, `BOSS_STAGE_EVERY = 5`.
- **NO `GRAVITY`** (D3).

**`src/util/rng.ts`** (PURE): `export type RNG = () => number`; `mulberry32(seed:number):RNG`
(byte-identical body); `range(rng:RNG, min:number, max:number):number`.

**`src/util/save.ts`** (PURE): `get<T>(key,fallback):T`, `set(key,value):boolean` (defensive);
`interface MetaState { currency:number; upgrades:{'1':Record<string,number>;
'2':Record<string,number>}; bestScore:number; bestStage:number }`; a frozen `DEFAULT_META`
(`currency:0`, empty per-player upgrade maps, `bestScore:0`, `bestStage:0`); `loadMeta()`
(spread-backfill over the stored object, then CLONE `upgrades['1']` / `upgrades['2']` so they
never alias the frozen default); `saveMeta(meta):boolean`. Save key `'tank-1990:meta'`.

### 5.3 Boot/runtime flow

`main.ts` builds ONE `Phaser.Types.Core.GameConfig`: `type: Phaser.AUTO`, `parent:'game'`,
`scale:{ mode:FIT, autoCenter:CENTER_BOTH, width:DESIGN_WIDTH, height:DESIGN_HEIGHT }`,
`physics:{ default:'arcade', arcade:{ debug:false } }` (NO gravity), `backgroundColor:'#0b0e14'`,
`scene:[BootScene, TitleScene, HubScene, GameScene, HUDScene, GameOverScene]`. The first entry
(Boot) auto-starts. A DEV-only `window.__game` handle is exposed behind the DEV flag (tree-shaken
from `build`), matching the reference, so a later smoke test can inspect the live scene without
production coupling.

**DEV-flag typing under strict `tsc` (D11 — resolves the AC2 green-gate hazard).** This repo, like
the reference, carries NO `/// <reference types="vite/client" />` and NO `vite/client` in
`tsconfig`'s `types`/`compilerOptions`, so under strict `tsc --noEmit` the property `import.meta.env`
is UNTYPED — a naive `if (import.meta.env.DEV)` does NOT typecheck (error: `Property 'env' does not
exist on type 'ImportMeta'`), which would make `npm run typecheck` RED and FAIL the Definition of
Done. To avoid that, `main.ts` MUST guard the DEV branch with the reference's **inline-cast form,
copied VERBATIM** (read-only `dead-cell/src/main.ts`):

```ts
// DEV-ONLY debug handle (stripped from the production build — Vite tree-shakes the import.meta.env.DEV
// branch out of `npm run build`). NEVER read by game code.
if ((import.meta as ImportMeta & { env?: { DEV?: boolean } }).env && (import.meta as ImportMeta & { env?: { DEV?: boolean } }).env!.DEV) {
  ;(window as Window & { __game?: Phaser.Game }).__game = game
}
```

We pin **option (a): the inline cast**, NOT option (b) (`/// <reference types="vite/client" />` + a
typecheck-visible `vite` dep). Rationale: the inline cast keeps `tsconfig.json` byte-identical to the
reference (no `types`/triple-slash divergence — D1), requires ZERO extra typecheck-visible type deps,
and the cast widens `ImportMeta` ONLY at this one call site (SOLID — no ambient `env` typing leaks to
the rest of the code). The implementer MUST NOT write the bare `if (import.meta.env.DEV)` — that is
the exact form that turns AC2 red.

**Scene state machine (stubs):**

- `BootScene.create()` → `this.scene.start('Title')` (no assets to load — programmer-art).
- `TitleScene.create()` → heading + start prompt (positioned from `DESIGN_*`, centered under
  FIT); `keyboard.once('keydown-SPACE'|'keydown-ENTER')` + `input.once('pointerdown')` →
  `scene.start('Hub')` (`once` so a held key can't double-fire).
- `HubScene.create()` → heading + a "START" prompt; key/pointer → `scene.start('Game')`. (The
  real two-column P1|P2 upgrade UI + shared-currency readout is a LATER feature.)
- `GameScene.create()` → draws ONE placeholder rectangle (a `Graphics` fill) so the scene
  visibly runs; launches the parallel HUD overlay via `this.scene.launch('HUD')`.
- `HUDScene.create()` → empty parallel overlay stub (a small corner label is fine; no live
  readouts yet).
- `GameOverScene.create()` → heading + prompt; key/pointer → `scene.start('Title')`.

### 5.4 Integration points with existing code

None — the target repo starts EMPTY, so F0 creates every file fresh. The contracts F0
establishes are the integration points LATER features extend:

- `constants.ts` names (grid/tank/bullet) are imported by the F2 generator + GameScene + HUD.
- `rng.ts` (`mulberry32`/`range`) is imported by the F2 generator + the verifier.
- `save.ts` `MetaState` / `loadMeta` / `saveMeta` are wrapped by a later `core/MetaState` and
  read/written by the Hub + GameOver.
- The scene set + the `Title→Hub→Game→GameOver` flow + the parallel HUD are the spine every
  later feature plugs into (entities into GameScene, upgrade UI into HubScene, readouts into
  HUDScene).
